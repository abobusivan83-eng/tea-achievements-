# TEST CHECKLIST — Android (ручное тестирование)

Использовать установленную **standalone** сборку (APK из EAS профиля `preview-apk`), не Expo Go — если не указано отдельно.

Отмечать: ✅ / ⚠️ (деградация) / ❌ (блокер).

---

## Окружение и данные перед прогоном

- [ ] На телефоне отключены прокси/VPN, которые ломают HTTPS (или они осознанны).
- [ ] Известны тестовый логин/пароль и ожидание статусов на бэкенде.
- [ ] Сертификат API доверен на устройстве (нет самоподписанных MITM проблем).

---

## 1. Доступность API и «холодный» старт

- [ ] Убить приложение из памяти (не только свайп с Recents полностью, при необходимости «Force stop» в настройках).
- [ ] Открыть приложение: нет черного экрана крэша без сообщения.
- [ ] Если `EXPO_PUBLIC_API_BASE_URL` не был задан в билде — ожидается читаемый экран ошибки конфигурации (не сырое падение).
- [ ] После успешной конфигурации: переход на экран логина или автологин без зависания.

---

## 2. Авторизация

### Логин

- [ ] Неверный пароль показывает сообщение ошибки без утечки внутреннего стека пользователю.
- [ ] Успешный логин ведёт в основную оболочку приложения с нижней панелью.

### Persist / Auto login

- [ ] После успешного логина: **полностью** закрыть приложение (force stop или перезагрузка).
- [ ] Открыть снова: пользователь всё ещё авторизован (токен из **SecureStore**), профиль синхронизируется (**fetchMe / bootstrap**).

### Logout cleanup

- [ ] Выйти из аккаунта.
- [ ] Открыть снова логин-экран.
- [ ] После входа другого пользователя (если возможно на стенде) или повторной попытке старых запросов: нет «подтягивания» данных предыдущего пользователя (query cache после logout очищается через событие `auth cleared`).

### Срок токена (регресс высокого уровня)

- [ ] Если токен истёк/exp неверен: приложение переводит к логину или показывает ожидаемое поведение без утечки чувствительных данных в UI.

---

## 3. Навигация и жесты

### Bottom tabs

- [ ] Все вкладки: Главная, Задания, Достижения, Уведомления, Профиль (названия соответствуют текущему UI).
- [ ] Переключение между вкладками без падений.
- [ ] Если есть бейдж уведомлений — счётчик обновляется после просмотра/прочитанных (поведение согласно реализации API).

### Вложенные стеки и переходы

- [ ] С главной: Магазин / Подарки / Рейтинг и возврат «Назад».
- [ ] Задания: список → деталь → назад свайп/gesture где поддерживается.
- [ ] Анимации переходов плавные на устройстве mid-range под нагрузкой.

### Safe area и клавиатура

- [ ] Контент не перекрыт вырезом статус-бара/notch там, где критично.
- [ ] На детальной странице задания поле текста поднимается при открытой клавиатуре (**KeyboardAvoidingView** в связке с `softwareKeyboardLayoutMode` на Android).

---

## 4. Задания — конвейер

### Список

- [ ] Pull-to-refresh обновляет список без дублей ключей карточек.
- [ ] Сегменты «доступные / выполненные» (или аналог) переключаются корректно.
- [ ] При пустых списках читается **empty state** (не просто белый экран).

### Карточка → деталь

- [ ] Открыть задание: заголовки, статус времени («активно/истекло») и награды отображены.
- [ ] Если задание не найдено в кэше — корректный fallback + «повторить / назад».

### Отправка доказательств

- [ ] Минимальная длина комментария обрабатывается (сообщение об ошибке).
- [ ] Прикрепление нескольких медиафайлов работает предел очереди.
- [ ] После отправки: индикация успеха (**toast**/сообщение) и переход статусов согласно API.
- [ ] После отправки экран синхронизируется после инвалидации списка заданий.

---

## 5. Медиа — загрузка и просмотр

### Выбор/gallery queue

- [ ] Добавление фото/видео из галереи.
- [ ] Превью в очереди, удаление, перемещение вверх/вниз.
- [ ] Если видео слишком большое для политики — предсказуемое сообщение (если настроено на клиенте/сервере).

### Прогресс аплоада и retry

- [ ] Прогресс-бар загрузки визуализируется.
- [ ] Симуляция обрыва сети показывает понятную ошибку; повторная попытка (`retry`/кнопка) адекватна.

### Полноэкранный viewer

- [ ] Полноэкран: свайп между файлами, pinch-zoom изображений, видео с контролами.
- [ ] Закрытие viewer по кнопке/cross.

---

## 6. Offline / нестабильная сеть

- [ ] Включён авиарежим: списки/экраны показывают ошибку и **повторную попытку** где реализовано (React Query паттерны).
- [ ] Восстановить сеть: refresh/pull-to-refresh возвращает данные без необходимости перезапуска приложения (если не требует дизайн иначе).

---

## 7. Профиль и вспомогательные экраны

- [ ] Профиль загружает **/api/auth/me** и отображает базовые поля.
- [ ] Выход затем блокирует видимость приватной информации.
- [ ] Магазин/подарки/рейтинг (если подключены): базовые сценарии без 500 в логах на стороне приложения пользователю.

---

## 8. Performance / память — полевые эвристики

### Low-end телефоны (ориентир: 3–4 ГБ RAM, старый SoC)

- [ ] Свайпы по вкладкам после 5–10 минут не приводят к убийству процесса из-за памяти.
- [ ] Список задач большой высотой не «зажёвывает» после быстрого скролла (регресс ручной без профайлера).
- [ ] Модал viewer на длинном списке вложений: открытие→закрытие многократно без сильного тормоза.

### Общие наблюдения

- [ ] После многих циклов навигаций нет экспоненциальных задержек (утечки известного рода должны воспроизводиться хотя бы косвенно).

---

## 9. Crash / Security sanity

### Crash сценарии

- [ ] Принудительно прервать выбор медиа (системный back) приложение живо.
- [ ] Принудительно kill во время активной загрузки — приложение восстанавливается без бутлуп-крэша (если нет ограничения по дизайну).

### Security

- [ ] Осмотреть локальное хранилище: невозможность прочесть JWT простым файлом приложения данных уровнем пользователя (ожидаемо Keychain/KSP).
- [ ] Никаких **console.log JWT** видимых в release (проект кодовая база очищена на уровень отсутствия console в `src`; при добавлении логирования использовать защиту `__DEV__`).

---

## 10. Версирование апдейта установки поверх APK

Обновление поверх более старой сборки если `versionCode` не вырос может быть отклонено Play внешней установкой может перезаписать — см. **`RELEASE.md`**.

Для каждого нового внешнего теста увеличивайте `android.versionCode` в `app.json` при необходимости.
